# MOV-422: Jev router trial design

Research date: 2026-09-30. This is a plan, not authorization to buy credits, install a proxy, or change live dispatch. “Measured” below means local dispatcher data or inspected source; “documented” means the linked vendor or project documentation; everything else is a hypothesis to test. The implementation issues linked from [MOV-422](https://linear.app/moviecal/issue/MOV-422) own the proofs and activation.

## Decision

Use [OpenRouter's hosted `typesafe/jev-router`](https://openrouter.ai/typesafe/jev-router) as the first live arm, **only after** a disposable Claude Code run proves tool use, accounting, model identification, and account-level restrictions. Evaluate [prismhq/jev-router](https://github.com/prismhq/jev-router) as the open-source arm on fixtures, then admit it to a second, separate live arm only if it can fail closed, enforce the same candidate/data policy, and preserve the worker tool protocol. Do not compare results from one arm against an earlier calendar period alone; keep a contemporaneous fixed-route control in each window. No live arm proceeds without the owner's separate credit and governance decision.

Among the named alternatives, `prismhq/jev-router` is the most useful comparator because its [MIT LiteLLM proxy](https://github.com/prismhq/jev-router#readme) offers an explicit candidate list and serves model responses. [zDud4s/jev-model-router](https://github.com/zDud4s/jev-model-router) has useful counterfactual accounting, but its broader CLI delegation and subscription paths add authority that this trial does not need; [lucianfialho/jev-model-router](https://github.com/lucianfialho/jev-model-router) is a Python selection library using the live full catalog, not a drop-in worker proxy. The more popular [gargpratyush/jev-router](https://github.com/gargpratyush/jev-router) keeps native subscription CLIs, but routes only at fresh user turns; a headless dispatcher run is one user prompt with many tool rounds, so it cannot test per-request switching here. These are source-based fit judgments, not measured quality rankings.

### Integration proofs required before activation

1. **Claude Code.** Installed CLI is 2.1.282. `workerInvocation()` passes model, effort, `--settings`, tool allowlist, and `stream-json`. OpenRouter documents `ANTHROPIC_BASE_URL=https://openrouter.ai/api`, `ANTHROPIC_AUTH_TOKEN`, and an explicitly empty `ANTHROPIC_API_KEY`. A disposable guarded run must demonstrate those flags still work with `typesafe/jev-router`, including one read/write tool round routed to a non-Anthropic model, provider refusal, reasoning/effort behavior, and truthful `result` usage. A page advertising tool support does not establish Claude Code compatibility across model families. If it fails, keep the hosted live arm Claude-only with an Anthropic-only model constraint **only if** that constraint is enforceable; otherwise do not activate it.
2. **Codex.** Installed CLI is 0.157.1, and MOV-401 runs provider transport in a guarded client while commands run in a network-denied executor. Its `--ignore-user-config` means custom provider fields must be passed in the dispatcher-owned invocation. [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference) supports `model_providers.<id>.base_url`, `env_key`, and `wire_api=responses`; test the exact CLI and native `exec-server` path against OpenRouter Responses. The client must gain only the approved OpenRouter egress, while executor egress remains denied. Codex participation is deferred until this proof; it is not needed to start a Claude-only arm.
3. **Router output.** [OpenRouter's APIs](https://openrouter.ai/docs/api/api-reference/anthropic-messages/create-messages) offer opt-in `X-OpenRouter-Metadata: enabled`; fixture capture must prove the actual served model, provider, effort, request ID, usage, and charge can be reconciled for *every* turn, including streaming and errors. The hosted model's public page does not guarantee each of these fields. The open-source proxy reports a response `model` field, but effort and price still need instrumentation.
4. **Restrictions.** Prove a key-level allowlist blocks disallowed downstream models; pin allowed inference providers, deny data collection, enforce ZDR where compatible, disable prompt logging, and check failure semantics. Reject the arm if these cannot be applied to router-selected calls. [OpenRouter's response cache](https://openrouter.ai/docs/guides/features/response-caching) is separate from provider prompt caching and is unavailable under account-level ZDR; do not count it as a savings source.

## Cost baseline and comparison

**Measured on this Mac:** `dispatcher usage export --since 2026-09-26T00:00:00Z` on 2026-09-30 selected 44 schema-2 dispatcher attempts across 24 issues (246 older/legacy rows excluded). Of these, 19 Claude default/Sonnet 5 attempts across 13 issues had 17 reported API-equivalent costs, totaling $10.15, median $0.53 for the reported attempts; 6 Claude strong/Opus 5.5 attempts across 6 issues reported $24.16 total, median $3.73. The other 19 attempts were Codex strong/GPT-6 Sol across 5 issues, with **no reported dollar cost**. Claude cost is an API-equivalent estimate on subscription, not spend; Codex cost and cache-write counters are not exposed. The export reports turns and durations for all 44, input/output/cache-read tokens for 42, and cost/cache-write for 23. An attempt can be failed, repeated, or a continuation; these figures are **not cost per finished issue**. No raw export or local ledger is committed.

For every trial issue, sum all attempts, continuations, repairs, and billable router decisions by issue ID. Join the eventual accepted/merged outcome and human review time. Primary measure: actual API invoice plus credit-purchase fee divided by **accepted finished issues**, separately by arm and matched control. Report aborted work and zero-finish denominators explicitly. Secondary measures: first-attempt accepted rate, wall time, retries, turns within each harness only, human rework minutes, provider-limit/credit consumption, cache-read ratio, and switches per issue. Compare the subscription arm both at marginal incremental cash cost ($0 until its quota binds) and fully allocated seat cost per completed issue (monthly seat price divided by all completed issues using it); name the allocation rule before results. Never compare Claude and Codex `turns` as the same unit.

For cache sensitivity, a model/provider switch makes previously cached context unavailable on the new endpoint. The extra input charge is approximately `cached_tokens × (new input price − old cache-read price) / 1,000,000`, plus any new cache-write premium. At 35K tokens and a hypothetical $3/M ordinary input with a 0.1× cache-read rate, that is about $0.095; at 357K it is about $0.964. These are **illustrations**, not observed switch costs or current provider quotes. Record per-turn cache read/write and price to compute the actual amount; if unavailable, report a range. OpenRouter's [Anthropic caching guide](https://openrouter.ai/docs/guides/best-practices/prompt-caching) documents 0.1× reads and 1.25× 5-minute writes for that provider, not a universal model price.

## Dispatcher and security design

Use a new explicit routed provider mode on an issue, preserving the existing `worker:*` and hand-applied `model:*` route for controls. Do not reinterpret `model:strong` as Jev or silently override a pinned model. A disabled-by-default runtime policy names the router arm, eligible issues, allowed worker, candidate/provider policy hash, trial ID, max admissions, spend ceiling, and UTC expiry; it cannot activate with a missing guard, credential, or price budget. Reuse MOV-383's lock-protected append-only assignment ledger, expiry/cap check at admission, attribution in manifest and usage, and stop command. Resumes/repairs retain their originally assigned arm and model policy. Router/provider errors defer the issue with a visible reason; no silent route to a different provider, model, or subscription. A separate operator stop disables future admission and leaves ongoing work auditable.

The implementation must update `docs/operators/local-execution.md`, `docs/operators/worker-routing.md`, `tools/dispatcher/src/worker-guard.mjs`, and `codex-containment.mjs` as applicable. Put an owner-approved, trial-scoped API key outside the repo in a mode-600 dispatcher credential store, behind the existing `needs-secrets`/human decision gate. A worker shell must never inherit it. Codex can keep the key in the provider client and remove it from the executor environment; prove that boundary. Claude needs a trusted local credential broker or equally strong design, since a key placed in the Claude process environment may leak to its `Bash` tool. The broker must inject auth only into an allowlisted upstream, never expose a raw forwarding endpoint to worker commands, and be tested with MOV-415's network-isolation work. Until that isolation exists, Claude live routing is blocked. Do not put keys in `.env.local`, the issue, a PR, `--settings`, or logged argv. This is a governance and new-secret decision for Adam before activation.

Append a bounded per-turn routing record to `routing-decisions.jsonl`: issue/attempt/turn/request ID, router arm and policy hash, requested/resolved model and effort, provider, input/output/cache tokens, provider charge, decision latency, fallback/error, and source of each field. Never log prompts, tool payloads, headers, or secrets. `usage export` must roll these into per-issue invoice totals without double-counting retries or cached reads. If the hosted endpoint hides served model or effort, stop the arm instead of inventing them.

## Bounded trial

1. **Fixture/readiness.** Offline protocol and confinement fixtures for both arms. Then one paid, disposable, non-private repo fixture per admitted arm to prove a tool loop, metadata, accounting, deny rules, and clean stop. A failed gate keeps that arm out of live routing; the other can proceed independently.
2. **Cohort.** In each 14-day window, cap new assignments at 12 routed and 12 contemporaneous fixed-route controls, matched in advance by `model:*` tier, issue size, risk, and worker. Use default and medium-risk issues first; exclude auth, migrations, secrets, high-risk work, and issues requiring human-only execution. Do not select based on early outcomes. Hosted first; open-source follows only after its specific gates. Keep each arm's maximum provider spend at a proposed $75, with an OpenRouter key budget and dispatcher meter; Adam approves or changes the cap before either starts. End on expiry, admission cap, spend cap, or explicit stop. A small cohort gives directional evidence, not a significance claim.
3. **Success and stop.** Prefer an arm only if actual API cost per accepted issue is at least 20% lower than the fully allocated subscription comparator **and** first-attempt acceptance is no worse by more than 10 percentage points, with no increase in median human rework. Also publish marginal cash comparison, even when it disfavors API. Stop immediately on a credential leak, forbidden model/provider, missing per-turn model/cost evidence, unexpected fallback, tool protocol corruption, guard escape, or spend cap; pause on two consecutive router failures or >25% first-attempt failure until reviewed. A 12-issue arm cannot establish tight confidence intervals, so borderline results mean extend by a newly approved capped trial or retain fixed routing.
4. **Rollback and decision.** `trial stop`/expiry/cap reverts fresh assignments to explicit baseline policy without daemon restart; in-flight attempts remain attributed and can finish, subject to the spend stop. Revoke the trial key, stop any local proxy, and preserve redacted ledger/evidence. Publish per-arm and control issue outcomes, cost derivation, switch/cache distribution, and the adopt/partial/drop decision; update routing and security docs. A shadow classifier on issue text is optional only as a cheap, separately capped diagnostic: it cannot measure per-turn switching or tool compatibility and must not silently relabel issues.
