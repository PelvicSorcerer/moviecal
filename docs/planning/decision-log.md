# Decision log

- Use Vercel Hobby for initial hosting.
- Use Supabase Free for initial auth and database.
- Use TMDb for movie metadata.
- Use iCalendar feed subscription rather than native calendar API integration.
- Use public GitHub repo, so secrets must never be committed.
- Keep architecture portable enough to self-host later if needed.
- Replace the GitHub-Project-centric, multi-cloud-agent dev-governance model with a Linear-based control plane and a local-Mac dispatcher. See `docs/governance/linear-information-architecture.md` and `docs/operators/local-execution.md`. Migration status below.

## Migration complete

All 12 stages of the Linear/GitHub/local-Mac dev-governance migration are done. Remaining open work is tracked as ordinary Linear issues, not migration stages, and none of it blocks using the system for real work — these are refinements, not missing prerequisites:

- `MOV-115` — **done.** Two-way GitHub sync enabled and verified 2026-09-08 (see Stage 5 above).
- `MOV-116` — **done.** Rescoped 2026-09-08 from "separate worker identity + formal PR approval" to `lane-review`, an automated independent review pass running as a required-CI-style status check (see [PR #272](https://github.com/PelvicSorcerer/moviecal/pull/272)).
- `MOV-118` — **done.** The dispatcher now reconciles worktrees in `"review"` against their real PR state every poll cycle (`pr-reconcile.mjs`): merged → `"merged"`, closed-without-merging → `"abandoned"`, both without manual intervention. Verified live on `MOV-104`/#281's real merge.
- `MOV-119` — **done.** `lane-review` ran informationally across 8 PRs (docs, dispatcher-internals, and one real app-code PR) with zero false positives and a well-calibrated first live AI-layer run; added to `master-protection`'s required status checks 2026-09-08 (repo owner action — ruleset changes stay outside what the dispatcher or any worker does). `master-protection` is now 5 of 5: `lane-baseline`, `lane-unit`, `lane-integration`, `lane-browser`, `lane-review`.
- `MOV-121` — **done.** Staged workflow-edit proposals let an authorized agent complete a CI-cutover issue end-to-end without a permission carve-out (see [PR #279](https://github.com/PelvicSorcerer/moviecal/pull/279)) — first exercised for real on `MOV-104`, which also became the first real app-code PR and the first real `lane-ios` CI run.
- `MOV-120` — install the dispatcher as a persistent `launchd` service. **Prepared, not activated.** The plist is filled in and installed at `~/Library/LaunchAgents/com.moviecal.dispatcher.plist`, pointing at a dedicated non-interactive worktree (`~/code/worktrees/moviecal/dispatcher-daemon`) rather than the interactive main checkout — see `docs/operators/local-execution.md` §Persistent service (launchd) for why. `launchctl load` has deliberately not been run. Its two original blockers are now both resolved (`lane-review` is a required check; `MOV-104` supplied a real app-code run, including a real worker-failure/retry cycle from an unrelated usage-limit reset) — remaining is purely the repo owner's own call on when to flip it on.

Two originally-planned items outside the 12-stage table are now also closed: the Codex CLI is installed on the local Mac (repo owner ran the global npm install; confirmed via `codex --version`, `codex-cli 0.153.4`), and the 7 Linear custom views listed in Stage 3 above are built. `MOV-120` (see above) is the only remaining originally-planned item, and is prepared but deliberately not activated — see its row above for current status, not this paragraph, which is intentionally not restated here to avoid the two going stale against each other.

**New open item, found 2026-09-08, not part of the original plan**: Linear notifications never fire for anything the dispatcher or an assistant session does, because every mutation is made under the repo owner's own personal API key and Linear suppresses notifications for your own activity. Root-caused; fix chosen (Linear's real Actor Authorization / `actor=app` OAuth feature, giving the dispatcher its own distinct workspace identity) but not yet planned or built — tracked as [`MOV-122`](https://linear.app/moviecal/issue/MOV-122), explicitly flagged as needing real planning (likely multiple issues, possibly a milestone) before implementation starts. Not a hard blocker for `MOV-120`, but worth resolving before leaning on the unattended service with real confidence — otherwise it could sit on `Needs Human Decision` indefinitely with nobody notified.
